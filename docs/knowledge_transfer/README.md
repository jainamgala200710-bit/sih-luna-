# LunaAlign Handoff Documentation

For the engineering team assuming maintenance of the SIH26166 repository, this document outlines the core architectural paradigm.

## Decoupled Architecture
LunaAlign is strictly decoupled into two isolated microservices.

### 1. The Mathematical Backend (`/backend`)
- **Framework**: FastAPI (Uvicorn).
- **Core Loop**: Found in `src/matching/classical/feature_matching_pipeline.py`.
- **Purpose**: All heavy $O(N)$ geometry calculations occur here. The backend NEVER renders UI elements. It relies entirely on REST APIs (for image ingestion) and WebSockets (for zero-latency telemetry broadcasting).

### 2. The Presentation Layer (`/frontend`)
- **Framework**: React (Vite).
- **Styling**: Vanilla CSS (No Tailwind dependency).
- **Core Loop**: `RegistrationDashboard.jsx` handles state management.
- **Purpose**: A lightweight UI that binds to the FastAPI WebSocket port (`ws://localhost:8000/ws/{session_id}`). It translates the JSON telemetry stream into visual progress bars and renders the Base64 images generated by the backend.

## Error Handling Paradigm
We do not allow OpenCV to throw standard C++ `Assertion failed` segfaults. All pipeline bottlenecks must be intercepted by the `PipelineExhaustionError` class (found in `src/utils/failure_warning_system.py`) to ensure graceful degradation.
